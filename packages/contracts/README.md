# packages/contracts —— 同名双份的共享面清单

`apps/server`（主应用）与 `apps/store`（授权商店）是两个**可独立部署**的项目：各自只
`import` 自己的包，互不 import（不变量 #43，见主 README）。因此有些概念在两边各留一份实现 ——
这是**有意**的，不是待清理的重复。

风险在于「两份会走散」：改了一边的压缩阈值、令牌白名单或日志噪音表，另一边不会报错，
只会在某个具体请求上表现成 422、不压缩或日志噪声，排查时看不出是两份实现。

本目录因此只放**清单**（不是代码）：`surfaces.json` 声明哪些名字的两份必须是同一份代码面。
`tools/check_invariants.mjs` 的最后一条不变量读它，按「剥掉注释与 docstring 后逐字相同」比较。
两侧各写各的模块说明不受影响（那本来就该各写各的）。

## 加一个契约面

1. 在 `surfaces.json` 的 `surfaces` 里加一项：`id`、`why`（写清走散时的静默症状）、
   `kind`（`code` 或 `set`）、`members`（两侧的文件 + 名字列表）。
2. 如果两侧今天写法不同但语义相同，先把文本收敛成一种（清单比的是文本，语义等价不会被识别）。
3. 跑 `node tools/check_invariants.mjs`，确认新面是绿的。

判断标准是「走散会不会静默失效」：会，就登记；只是两个项目各自需要不同行为（例如商店没有
流式代理通路，所以没有 `BYPASS_PATH_PREFIXES`），就不要登记 —— 登记了反而会逼着后来的人把
有意的差异抹平。
