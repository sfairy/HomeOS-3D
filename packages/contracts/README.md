# packages/contracts —— 同名双份的共享面清单

`homeos-3d/backend/src`（主应用）与 `homeos-store/backend/src`（授权商店）是两个**可独立部署**的项目：各自只
`import` 自己的包（包名均为 `src`），互不 import。因此有些概念在两边各留一份实现 ——
这是**有意**的，不是待清理的重复。

风险在于「两份会走散」：改了一边的压缩阈值、令牌白名单或日志噪音表，另一边不会报错，
只会在某个具体请求上表现成 422、不压缩或日志噪声，排查时看不出是两份实现。

本目录因此只放**清单**（不是代码）：`surfaces.json` 声明哪些名字的两份应对齐。
改动后请人工对照两侧实现。

## 加一个契约面

1. 在 `surfaces.json` 的 `surfaces` 里加一项：`id`、`why`（写清走散时的静默症状）、
   `kind`（`code` 或 `set`）、`members`（两侧的文件 + 名字列表）。
2. 如果两侧今天写法不同但语义相同，先把文本收敛成一种。
3. 人工核对两侧成员是否仍同义。

判断标准是「走散会不会静默失效」：会，就登记；只是两个项目各自需要不同行为（例如商店没有
流式代理通路，所以没有 `BYPASS_PATH_PREFIXES`），就不要登记 —— 登记了反而会逼着后来的人把
有意的差异抹平。
